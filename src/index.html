01 · FIRST REFERENCE

A name in the bytes. Who uses it?

Open a tiny compiled C program. Find its marker string, follow the reference, and see what the caller passes into the helper.

Hint

Find SPECTRA_FIXTURE_ONLY in Strings. Open its code references. The nearby call is your next stop.

Walkthrough

The marker is readable data. main passes its address to fixture_helper. The helper reads the first byte. Reconstructed C should show that access; the source is in the lesson download. An interesting string alone didn't tell us any of that.

02 · DECODED AT RUNTIME

Catch the string becoming readable.

A harmless XOR loop writes into scratch memory. Watch one write, save an experiment, then follow the whole loop.

Hint

Add a write watchpoint at 0x60000000 for 64 bytes. Run, inspect the change, then remove the watchpoint to finish. Capture memory into Recovery lab.

Walkthrough

Each source byte is XORed with 0x5a and written to scratch. The captured result is https://decoded.example/config. Save a checkpoint before changing an input; restoring it replays your experiment and checks its final state.

03 · HARDWARE ROUTINES

Same idea. Different CPU.

Add two numbers, follow the return, then compare the assembly with reconstructed C.

Hint

Initialize first. Set arguments to 2 and 3: R0/R1 on ARM, X0/X1 on AArch64, A0/A1 on RISC-V and MIPS. Run until return. The Decompile view is already mapped to the same bytes.

Walkthrough

ARM and RISC-V return 5 in their first argument register. MIPS returns 6 in V0: the instruction after JR executes in its delay slot and adds one. SPECTRA steps that pair together. An emulator models the routine; it hasn't booted a device.

Raw firmware mapping & ABI assumptions
Thumb entry addresses are even; select Thumb explicitly for mixed-mode code. RISC-V includes compressed instructions. Ordinary MIPS keeps branch delay slots; microMIPS, MIPS16, R6, n32 and ARM BE8 need separate profiles. AArch64 big endian means big-endian data with little-endian instructions. High addresses must fit the supported exact range.
Tell Ghidra the types you know
These feed the real decompiler. Use registered types such as uint32_t, int32_t and char*. This is Ghidra’s C declaration parser, not a C++ compiler. Assumptions save after successful decompilation, by function address and language. Saved signatures and declarations also inform callers in that same language. Local-variable notes remain annotations.
Structure workspace
Put names on offsets. Save a layout, inspect its bytes, then use Name * in a function signature. Saved declarations are shared by functions using the same Ghidra language and ABI. Packed layouts, bitfields and nested types need the manual C declaration controls.

Load base, raw bytes & session assumptions
Static PIE startup normally relocates its own pointers. The default keeps that code observable. The advanced option applies validated relative relocations before an alternate entry; skip self-relocating startup. START VA is a loaded address (linked address + load bias).
Bare routine: file mappings, zeroed stack and scratch, zeroed registers and flags 0x2. Supply its arguments. Windows model: zero-filled virtual sections, base relocations, import traps, TEB/PEB, TLS callbacks, then EXE/DLL entry. CPU is selected from the file. Writes into executable pages still stop; RW allocations can be filled and changed to RX with VirtualProtect. No SEH, threads, kernel, CLR, real DLL code, or full Windows OS. Unknown APIs stop with their name.
Linux model: little-endian static ET_EXEC on x86, x64, ARM/Thumb EABI5 or AArch64, plus ARM/Thumb static PIE with local R_ARM_RELATIVE records. Loads PT_LOAD and BSS, builds argc/argv/env/auxv, and models a bounded syscall set. ARM supports a single thread pointer and TPIDRURO reads; PT_TLS layout is not supplied. No dependency linker, threads, signals, kernel or live network. Select Bare routine for an isolated function.
Scratch: 0x60000000 · Stack: 0x70000000 · 64 KiB each · 16 MiB mapped-memory cap
