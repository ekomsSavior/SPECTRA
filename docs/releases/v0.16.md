# SPECTRA v0.16 — Persistent observations and streamed evidence

This release extends the four v0.15 evidence workflows. It does not start the remaining feature backlog or publish the beginner/intermediate manuals.

- **Recording:** explicit 2–64 MiB / up to 100,000-instruction budgets, globally ordered observations, transactional IndexedDB segments, mapping lifecycle, paged search, streamed checksummed NDJSON, interruption/gap labels and bounded event alignment. Documented uncompressed x64dbg v1 and Chrome JSON adapters import inert evidence. Two opened recordings can travel with selected bundles/projects.
- **Evidence:** incremental SHA/CRC and stored ZIP production, browser-private file streaming, explicit completed-file save link, 16 MiB fallback, cancellation, temporary-file cleanup and incomplete-file rejection. Immutable source snapshots and restoration still consume storage/memory. Full-workspace ZIP saves retain the older in-memory path.
- **Lessons:** five six-stage routes, per-stage missing-evidence instructions and navigation, version migration, exact fixture identity, current-observation guards and historical restored milestones.
- **Mapping:** map/protect/unmap history at a selected event; original image provenance removed on unmap; rebase/load-bias evidence; ELF PN_XNUM; thin Mach-O 32/64 LE/BE including SG_HIGHVM; zero-fill/high-address/overlap cases; same-length transform coordinates distinguished from compression provenance. Broader mapping does not add process loaders.

## Verification

385 automated checks passed: 340 Node test cases, 7 real managed WASM checks, 8 managed dependency checks, and 30 generated .NET harness checks. Tests cover incremental digests, bounded archives, corrupted/truncated/unsafe input, recording order across segments, incomplete/budget history, actual Unicorn observations beyond 200 rows, event alignment limits, mappings, adapters and lesson provenance. Existing native/managed/DiE/Linux/Windows/hardware regressions remain green.

Actual desktop Chromium browser checks: 221-instruction built-in decoder recording; saved segments after reload; mapping at a recorded event; 100-row pagination; 6/6 decoder lesson progress saved and restored as historical; explicit bundle inventory; local file upload, checksum review and restoration of a 500-instruction benign recording under production CSP; imported evidence and engine mismatch labels; no sample execution on restore. Phone-width DOM checks use 390 px and are **not** a physical device test.

Private browser measurement harness wrote and verified 1, 8, 24 and 64 MiB stored ZIP members through OPFS with 64 KiB maximum working chunks. The 64 MiB case took about 15.8 seconds including prepare/write/read verification; reported JS heap during writing peaked around 40.5 MB on that desktop run. This excludes Blob, WASM, browser and OS memory, and is not a total-memory or modest-device claim. A 4,000-record IndexedDB run preserved all records across nine segments. Cancelled OPFS output was rejected as incomplete. Raw measurements are in [the verification data](v0.16-browser-measurements.json).

## Acceptance still open

Actual iPad/iPhone Safari save-to-Files/import/restore, VoiceOver, keyboard assistive-technology use, tab-eviction behavior and modest-device memory measurements remain pending. The in-app desktop browser exposed prepared file links but did not deliver either the app's download or a plain static-file control to the local Downloads directory; that download handoff is not marked passed. Parsing/restoration was checked using local fixtures through the file picker. [Safari acceptance route](../SAFARI-ACCEPTANCE.md) specifies the remaining user-device checks.

The four follow-up areas are implemented and desktop-verified, **not declared fully accepted on every device**. Resolve the above checks before starting bounded time travel or the other proposals. No arbitrary reverse-step, verified external replay, complete Windows/Linux/device environment or lossless memory log is claimed.
