# SPECTRA v0.14 — Continue disassembly

Disassembly no longer ends at the first 60,000-instruction budget. When code locations remain queued, **Continue analysis** resumes the same static traversal. It adds up to 60,000 instructions and 4 MiB of decoded-byte capacity per click, with cumulative ceilings of 1,000,000 instructions and 16 MiB. Each request has a 45-second worker deadline.

The initial pass remains small. Larger passes consume more memory; save your investigation first on a modest device. Cancel and timeout keep the last completed result. After cancellation, continuing rebuilds that depth before extending it. Selections, filters and analyst names remain in place. A completed queue releases the worker.

The traversal retains pending call/branch targets, handles a MIPS delay-slot boundary without duplicating edges, and expands indirect hypotheses only once the direct frontier is exhausted. Four indirect-expansion rounds are allowed per request; additional queued work can continue. Function membership work is bounded independently.

Coverage now reports decoded bytes and mapped executable bytes. An exhausted queue is not proof that every function, data reference or runtime destination was found. Architecture limitations are reported separately from capacity: AArch64 no longer displays the unrelated mixed ARM/Thumb warning. Raw-range analysis remains available for analyst-selected code outside discovered paths and replaces the current code result as before.

Investigation projects retain the cumulative budget and selection. Import checks the budget bounds and recomputes code locally; live worker state is not serialized. Existing projects keep the old default. Code JSON exports include limits, pending-work status and byte coverage. Binary comparison retains its own default bounded analysis.

Only static parsing/disassembly was used; the sample is not included in the release.
