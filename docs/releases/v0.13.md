# SPECTRA v0.13 — ARM static PIE in Debugger lab

ARM/Thumb EABI5 static PIE can now initialize in the existing debugger. The loader uses ELF program headers, maps PT_LOAD and zeroed BSS at a deterministic load bias, rebases the entry and startup auxiliary vector, and validates bounded R_ARM_RELATIVE tables. Section names are not required.

## Use it

Open the ELF, choose **Debugger lab**, and use **Use detected setup**. The Linux ELF process model and ARM/Thumb CPU should be selected. Leave **ARM PIE relocations** on **Program startup (default)**, then initialize. Initialization loads the image without executing instructions. Step or run when ready. The default bias is `0x10000000`; an entry linked at `0x3400` starts at `0x10003400`.

Static PIE startup often relocates its own pointers. The default deliberately leaves that work to the program so it remains visible in stepping and memory watchpoints. For isolated analysis, the advanced loader-owned mode applies validated relative relocations before an analyst-selected alternate entry. It rejects the original entry to avoid applying the same bias twice. The analyst still needs to choose an entry that skips the self-relocator and supply any other state that routine needs.

**Load ARM PIE demo** provides a benign self-relocating example; select Thumb first to load the Thumb variant. Watch four bytes at `0x10001000`: startup changes the pointer from `0x1020` to `0x10001020`, then writes `pie` and exits. Assembly and reproducible fixture generation are included under `fixtures/arm-pie/`.

## Startup and execution changes

- Single-thread ARM `set_tls`, `get_tls`, `set_tid_address`, clear-tid on modeled exit, and the narrow TPIDRURO read instruction. The auxiliary vector advertises this modeled TLS capability only.
- Image-page `mprotect`, bounded anonymous mappings, and MAP_FIXED guard pages within modeled brk allocations. Other occupied mappings cannot be replaced.
- ARM's O_LARGEFILE flag for bounded virtual regular files. No host file access is introduced.
- Unsupported syscalls record their number, arguments, instruction address and reason before stopping.
- ARM conditional `addls pc, ...` is handled as ordinary control flow; actual flag-setting exception-return forms remain blocked.
- Relocation ownership, process state and memory protections participate in saved setup and verified checkpoint replay.

## Verified scope and limits

The local reported ARM ELF (`97b2…5802`) validates all **522 relative relocations**, initializes at `0x10003400`, and advances through self-relocation, TLS setup, memory allocation and virtual file operations in bounded CPU emulation. The observed run stops after **35,084 instruction attempts** at **clock_gettime64 (syscall 403)**, an environment operation not yet modeled. This is useful startup debugging, not evidence that the whole program can complete. No sample, reconstructed sample code, or sample-derived output is distributed with the release.

Native dependency linking, PT_INTERP/DT_NEEDED, PT_TLS image layout, symbol-based/RELA/RELR/PLT relocations, threads, signals, a full kernel and live network remain unsupported. Non-ARM PIE profiles remain blocked. The existing static ET_EXEC profiles are retained. Malformed or unsupported relocation layouts fail preflight. The loader caps relocation tables at 8,192 records, images at the existing 16 MiB mapped-memory budget, and retains execution limits.

New automated coverage uses real ARM and Thumb WASM emulation at two load biases: self/loader relocation, output, BSS and auxiliary vectors, breakpoints, relocation watchpoints, checkpoint replay, guarded memory, protection changes, TLS operations, ARM file flags, malformed input and unsupported instruction boundaries. Full regression and browser verification are recorded in `release-verification.json`.
