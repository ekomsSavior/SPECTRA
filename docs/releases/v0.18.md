# SPECTRA v0.18 — APK / DEX reconstruction

Android packages now have a real Java reconstruction path in Decompile. The local worker translates selected DEX classes through dex2jar and reconstructs Java with Vineflower. It handles standard DEX 035 and 037–040, including multiple `classes*.dex` members, without uploading or executing the sample.

## What analysts can do

- Search a paginated class inventory, inspect declared methods and fields, and reconstruct one class at a time.
- Follow unambiguous in-package class/method/field references across DEX files. These are symbolic references, not exact source-line-to-instruction maps.
- Inspect bounded original method bytes with DEX hash and byte range.
- Decode binary Android manifests and resource XML; inspect a bounded resource table while retaining numeric references and configuration bytes.
- Download package evidence or open a DEX/native library as a child investigation. Compressed members retain their provenance without an invented linear parent offset.
- Export Java and structured evidence; preserve the selected reconstruction in workspaces, projects and the Analysis evidence group.
- Complete a sixth resumable lesson using a small unsigned multidex fixture. Its six stages require observed package/manifest/source/method evidence, notes and an evidence inventory. Imported milestones stay labeled historical.

The engines, licenses, pinned provenance, browser bridge source and corresponding upstream source archives are included in the source/offline release. No additional service or account is needed for analysis.

## Boundaries

Input is capped at 64 MiB. DEX admission allows up to 32 images, 32 MiB each and 64 MiB combined, with 50,000 total classes. Selected-class translation is bounded to 64 supporting classes and 16 MiB of class bytes. Reconstruction output is capped at 2 MiB. Startup and individual jobs have timeouts, and Cancel terminates the worker.

APK signatures are not verified. Android framework dependencies are not supplied; missing definitions and ambiguous duplicate identities remain visible. This release does not execute Android apps, merge split packages, recreate Kotlin source or an installable project, disassemble smali, or unpack protected runtime-loaded code. Resource decoding is partial; unsupported compact entries are identified. Reconstruction may be incomplete or wrong and must be checked against original evidence.

## Verification

The full automated suite passed 408 checks: 379 Node/TAP checks, seven managed WASM checks, eight local managed dependency checks and fourteen harness metadata/export checks. The 23 Android checks cover real reconstruction, cross-DEX references, duplicate identities, resources, malformed/budgeted input, project round trips, lesson provenance, worker messages, byte transfers and cancellation. The Android checks were repeated after final parser/UI changes.

Both benign reconstructed Java classes were compiled and compared with expected behavior across 2,977 input/output cases, including branches, loops, switch cases and exception behavior. A separate public Androguard APK fixture was inspected: 2,119 classes, 438 package members and 3,469 decoded resource entries; a class was reconstructed successfully. That APK is test input only and is not redistributed in the release.

Browser checks cover class/source/method navigation, the six-stage lesson, evidence preparation and historical progress after save/reload/resume. Narrow browser layout checks are distinct from physical-device testing. Android reconstruction on physical iPad/iPhone/Android and assistive-technology coverage remain open. Release/package/deployment evidence is recorded in `release-verification.json`.

The private beginner/intermediate manuals are unchanged and unpublished.
