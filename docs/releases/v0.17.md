# SPECTRA v0.17 — Bounded routine history

Debugger lab can now keep an opt-in timeline for x86/x64 bare routines. Step backward or forward, seek a numbered boundary, or search backward for an address/conditional breakpoint or a recorded memory access. Earlier state is reconstructed in a fresh emulator and verified before it appears in the existing register, memory, assembly and trace panels. The latest live experiment stays intact.

Historical views are read-only. Return to latest to continue running or editing. Captures and session reports identify historical state; an exported checkpoint preserves the selected verified state. Imported trace observations cannot initialize this history or become verified replay.

## Scope

Start history immediately after initialization. Choose 256, 512 or 2,048 actions; instruction attempts and analyst edits both count. Admission is limited to 2 MiB mapped memory and 4 MiB serialized timeline metadata. A budget hit pauses before the next action without evicting older boundaries. These limits do not represent total browser memory.

Reverse access search retains up to 128 access observations per action and reports uncertainty when clipping could hide a match. Replay checks supported register state, mapped pages and permissions, counters, call tracking, edits, terminal state and recipe/model state. A failed or cancelled reconstruction returns to the latest live session.

This first implementation replays from initialization. Persistent/imported timelines, branching, periodic executable checkpoints, process and hardware history, syscall/MMIO reversal, and faster long histories remain open. Routine history and persistent observation recording are separate capture modes. The timeline does not survive a reload; export needed evidence first.

## Verification

Automated history coverage uses the real Unicorn and Capstone engines, including x86/x64 writes and edits, the complete 221-instruction decoding demo, reverse conditions and retroactive watchpoints, address-hook output, partial faults, budgets, divergent replay, cancellation, failed verification and worker concurrency. The full regression results are recorded separately in the release verification record.

Desktop browser checks under production security headers: complete decoder run; seek to before the first decoded byte; forward to its write; return to the untouched final result; reverse search with a watchpoint added afterward; historical mutation controls disabled; a selected historical checkpoint and capture carry the correct state. The 390 px layout has no horizontal page overflow. Physical-device history performance and VoiceOver remain unmeasured.

The Church reported successful iPad and phone testing of the prior release on 18 October 2026 and authorized continuing the backlog. Exact models, OS versions and detailed test steps were not supplied; that report is not a blanket accessibility or memory benchmark. The beginner/intermediate manuals remain unpublished.

The debugger engine fingerprint changes with this release. Older checkpoints remain inspectable evidence; verified replay requires their matching engine. Keep the corresponding older offline release when reproducing an older experiment.
