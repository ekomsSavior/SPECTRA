DECODER CONTRACT / Windows x64 integer ABI:
RCX points to encoded bytes; RDX points to equally large writable output;
R8D is the u32 count; R9B is the initial 8-bit key. It returns count in EAX.
The caller must validate both buffers. This routine does not parse headers.
The capture header supplies count, data offset and seed; apply them manually.
R9B and R10B are low bytes of R9/R10; EAX is low 32 bits of RAX.

GUARD CONTRACT / pure predicates; no memory access:
ECX=total buffer length, EDX=cursor, R8D=declared VALUE length (all u32).
Two bytes of tag/length header precede the value at cursor.
Return EAX=1 if accepted, EAX=0 if rejected. The same API is tested with
full u32 lengths to expose arithmetic errors. The capture's length field
is only u8, so its particular records CANNOT supply 0xffffffff.
Do not claim that this wider API test proves an exploit in the capture parser.
