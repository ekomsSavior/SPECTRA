# SPECTRA community RE roadmap

Owner and home: Church of Malware, https://spectra.churchofmalware.org/. Public source destination: https://git.churchofmalware.org/ek0mssavi0r/SPECTRA. The app is not being moved to another host.

Authorized scope: the six community workstreams plus ARM/RISC-V/MIPS hardware workflows. v0.7 implements a tested first release across them; it does not claim parity with every IDA/Ghidra workflow or a complete OS/device environment. The deployed baseline before this release is v0.6. Deployment and repository publication are recorded separately in release-verification.json.

1. **Saved investigations and debugger controls — implemented and locally tested.** Hash-checked versioned ZIP bundles, original/recovered/dependency/comparison bytes, code names/notes/bookmarks, engine type assumptions, tool/harness settings and replay experiments. Explicit IndexedDB save/resume and opt-in autosave. Over/out, conditions, read/write watchpoints, verified cancellable replay and checkpoint comparison. Full document reload/resume verified in browser. Browser storage eviction still requires portable exports.
2. **Connected analysis — implemented.** Strings → references/callers → assembly/functions → real decompilation and prepared experiments. Address-based renames follow views and native symbols. Engine-applied function signatures and type declarations change Ghidra output. Local variable hypotheses remain labeled annotations; per-variable engine editing and richer indirect-flow/type recovery remain future work.
3. **Hardware workflows — implemented with explicit scope.** Ghidra ARM/Thumb/Cortex/AArch64, RV32/RV64+C and MIPS32/64 profiles; load address/endian/ABI controls, guarded unsupported profiles and lazy large specs. RISC-V disassembly and AArch64 instruction-order correction. Separate bounded integer-routine emulators, tested interworking, system stops, MIPS slot preflight and replay. No FP/SIMD, complete devices, OS/boot or arbitrary CPU-model selection is claimed. v0.9 adds explicit ARM MMIO response recipes.
4. **Binary/function comparison — implemented and tested.** Two local versions; strings/import changes; exact decoded bytes, symbol candidates and shape heuristics separated; ambiguity preserved. Side-by-side assembly and actual reconstructed C verified on a benign +1 patch. Comparisons save the second file and recompute evidence on resume. Managed-semantic diff and stronger cross-architecture matching remain future work.
5. **Thick clients, firmware and optional native debugging — implemented with platform limits.** Exact-identity local managed dependencies, saved setup recipes, AnyCPU/x86/x64 modern/Framework harness templates. Modern runtime/proxy tests pass; Framework 4.8 is compile-tested, Windows execution unverified. ZIP/USTAR/PAX/newc/crc CPIO/gzip extraction is bounded with child provenance; SquashFS unsupported. Experimental Linux/GDB companion includes same-origin pairing UI and tested native controls. Windows/CLR and hardware debugger adapters remain future platform work.
6. **Learning, community and access — implemented; publication tracked separately.** Optional contextual explanations, benign source/compiled exercises, hints/walkthroughs/evidence checks, contribution/export/engine-build documents, complete local assets, source/corresponding-source archives and an offline release. Budget/performance measurements recorded on the test host; a real low-end laptop matrix is still needed. Source is published on Church Git; complete source and offline downloads are also available on the site.

## Release rules

Keep everything free, monochrome, local for sample analysis and usable without an account. Publish actual implementations and measured verification; keep uncertainty and unsupported behavior visible. No mocked decompiler results or fabricated API success. Native execution is always an explicit analyst-controlled action. Preserve Cloudflare challenge/per-IP protections, source/licenses and a rollback path. Treat continued research as continued research.

## v0.8 browser detection

Real DiE 3.21 with its matching database runs locally on demand, with explicit heuristic labels, raw evidence, report export and sample-bound save/resume. No additional user setup or native debugger bridge is introduced. ExeInfoPE and dnSpyEx integration are outside this release. See docs/DETECTION.md and the release verification record.

## v0.9 controlled experiments

All five middle-ground workstreams are implemented: native integer/pointer function inputs; saved environment recipes and address/API hooks; focused x64/AArch64 static Linux ELF startup/syscalls; ARM/Thumb/AArch64 captured-memory/MMIO experiments; observed coverage and isolated input batches. The existing emulation, recovery and project workflows retain their bounds. See docs/EXPERIMENT-LAB.md and release-verification.json for scope and actual verification. Complete Windows/Linux systems, ARM board boot, arbitrary OS APIs, threads and full runtime compatibility remain deferred.
